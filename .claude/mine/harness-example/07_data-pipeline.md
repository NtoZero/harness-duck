# 데이터 파이프라인 설계 하네스 — 예시 프롬프트

## 기본 프롬프트

```
데이터 파이프라인 설계 하네스를 구성해줘. 스키마 설계, ETL 로직, 데이터 검증 규칙,
모니터링 설정을 계층적으로 위임하는 에이전트 팀.
```

## 구체적 변형 프롬프트

### 이벤트 기반 파이프라인
```
사용자 행동 이벤트를 수집해서 분석 가능한 형태로 변환하는 데이터 파이프라인을 설계해줘.
스키마 설계자가 이벤트 스키마를 정의하고,
ETL 엔지니어가 변환 로직을 구현하고,
검증 전문가가 데이터 품질 규칙을 작성하고,
모니터링 설계자가 알림 조건을 설정하는 팀.
계층적 위임으로 스키마가 먼저 확정되면 나머지가 병렬로 진행해야 해.
```

### DB 마이그레이션 파이프라인
```
PostgreSQL → BigQuery 데이터 마이그레이션 파이프라인을 설계해줘.
소스 분석 → 타겟 스키마 설계 → 변환 규칙 정의 → 검증 쿼리 작성 →
모니터링 대시보드 설계. 각 단계를 전문 에이전트가 담당하되,
상위 설계자가 전체 일관성을 관리하는 계층적 위임 팀을 구성해줘.
```

### 실시간 스트리밍 설계
```
Kafka 기반 실시간 데이터 처리 파이프라인을 설계하는 하네스를 구성해줘.
토픽 설계, 컨슈머 로직, 스키마 레지스트리, Dead Letter Queue,
모니터링/알림을 각각 전문가가 설계하고 아키텍트가 통합하는 팀.
```

## 예상 아키텍처

- **패턴**: 계층적 위임
- **실행 모드**: 에이전트 팀
- **팀 구성**: schema-designer(1단계) → etl-engineer + validation-expert + monitoring-designer(2단계 병렬) + architect(리더/통합)
- **핵심**: 스키마 확정 후 나머지 에이전트가 병렬 진행, architect가 의존성 관리 및 일관성 검증
- **산출물**: 스키마 정의서 + ETL 코드/설정 + 검증 규칙 + 모니터링 설정 + 통합 아키텍처 문서
