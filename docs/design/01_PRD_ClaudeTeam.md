## 1. 개요

### 1.1 제품 비전

ClaudeTeam은 **독립된 Claude Code 터미널 세션들을 하나의 에이전트 팀으로 조직화**하는 Electron 데스크톱 앱이다. 각 세션은 서로 다른 레포지토리(또는 디렉토리)에서 동작하며, 내장된 메시지 채널을 통해 에이전트 간 구조화된 소통을 수행한다.

### 1.2 문제 정의

현재 Claude Code의 멀티 에이전트 활용에는 다음과 같은 한계가 있다:

**레포지토리 격리 문제:** 마이크로서비스 아키텍처에서 프론트엔드·백엔드·인프라 레포가 분리되어 있으면, 하나의 Claude Code 세션으로는 전체 시스템을 다룰 수 없다. 각각 별도 터미널을 열어야 하고, 사이의 소통은 개발자가 수동으로 복사-붙여넣기해야 한다.

**컨텍스트 단절:** 프론트엔드 개발 중 백엔드 API 스펙이 필요하면, 개발자가 직접 백엔드 레포를 열어 확인하고 다시 프론트엔드 세션에 전달해야 한다. 이 과정에서 컨텍스트 손실과 시간 낭비가 발생한다.

**기존 Channels의 한계:** Claude Code Channels(2026.03.20 출시)는 Telegram/Discord를 통한 원격 소통을 지원하지만, "에이전트↔에이전트" 직접 통신은 설계 목표에 포함되지 않았다.

### 1.3 타겟 사용자

- 마이크로서비스 아키텍처를 운용하는 개발팀(2~5개 레포)
- 풀스택 개발자가 프론트/백을 오가며 작업하는 경우
- 기획 문서 기반으로 구현 검증이 필요한 1인 개발자
- 에이전트 기반 개발 워크플로우에 관심 있는 얼리어답터

## 2. 핵심 유저 스토리

### US-01: 에이전트 팀 구성

> 개발자로서, 프로젝트의 각 레포지토리(프론트엔드, 백엔드, 인프라)에 역할이 지정된 Claude Code 세션을 한 화면에서 관리하고 싶다.

**인수 조건:**
- 새 에이전트를 생성할 때 이름, 작업 디렉토리(절대경로), 역할(CLAUDE.md 내용)을 지정할 수 있다
- 에이전트는 지정된 디렉토리에서 `claude --channels` 플래그와 함께 시작된다
- 사이드바에서 모든 활성 에이전트의 상태(실행 중/대기/오류)를 볼 수 있다

### US-02: 에이전트 간 메시지 교환

> 프론트엔드 에이전트가 백엔드 에이전트에게 "@백엔드 회원가입 API의 응답에서 `ci` 필드가 누락되어 있어요. 원인 파악해주세요"라고 보내면, 백엔드 에이전트가 자기 레포에서 해당 코드를 찾아 분석 결과를 응답으로 보내고 싶다.

**인수 조건:**
- 메시지는 `@에이전트명` 멘션으로 수신자를 지정한다
- 채팅 UI에서 모든 에이전트의 메시지가 시간순으로 표시된다
- 멘션된 에이전트만 해당 메시지를 수신하고 처리한다
- 사용자(Human)도 채팅에 직접 참여하여 지시할 수 있다

### US-03: 파일 참조 및 공유

> 에이전트 간 소통 시 절대경로로 파일을 첨부하면, 수신 에이전트가 해당 파일을 직접 읽어서 내용을 파악하고 싶다.

**인수 조건:**
- 메시지 내에 절대경로(`/Users/dev/project/src/api/users.ts`)가 포함되면 파일 참조로 인식한다
- 수신 에이전트는 해당 경로의 파일을 직접 읽을 수 있다 (로컬 파일시스템 접근)
- 채팅 UI에서 파일 참조는 클릭 가능한 링크로 표시되며, 미리보기를 지원한다

### US-04: 기획 문서 기반 구현 검증

> 백엔드 에이전트가 커밋 전에, 공유된 기획 문서를 참조하여 구현이 요구사항에 부합하는지 셀프 검토하고 결과를 팀 채팅에 보고하고 싶다.

**인수 조건:**
- 팀 설정에서 공유 문서 경로를 등록할 수 있다 (예: PRD, API 스펙 문서)
- 에이전트의 CLAUDE.md에 "커밋 전 기획 문서 대조 검토" 지시를 포함할 수 있다
- 검증 결과를 팀 채팅에 자동으로 게시한다

### US-05: 권한 승인 관리

> 개발자로서, 여러 에이전트가 동시에 요청하는 권한 승인을 한 곳에서 처리하고 싶다.

**인수 조건:**
- 권한 승인 요청이 발생하면 앱 내 알림으로 표시된다
- 중앙 대시보드에서 모든 에이전트의 승인 대기 항목을 확인하고 승인/거부할 수 있다
- 에이전트별 자동 승인 규칙(예: 읽기 전용 작업은 자동 승인)을 설정할 수 있다

### US-06: CLI MCP 도구로 팀 제어 (tmux 스타일)

> 개발자로서, 별도의 터미널에서 CLI 명령으로 에이전트 팀에 메시지를 보내고, 상태를 조회하고, 파일을 읽고 싶다. Electron 앱 UI 없이도 tmux처럼 조작 가능해야 한다.

**인수 조건:**
- `claudeteam msg @백엔드 "회원가입 API 스펙 확인해줘"` 같은 CLI 명령으로 메시지 전송 가능
- `claudeteam read /path/to/file` 로 에이전트의 작업 디렉토리 파일을 읽을 수 있다
- `claudeteam status` 로 모든 에이전트의 현재 상태를 터미널에서 확인 가능
- Claude Code 세션 내에서 MCP 도구로도 동일 기능을 사용할 수 있다 (예: 독립 터미널의 Claude가 `team_message`, `team_read_file` 도구를 호출)

### US-07: 독립 터미널에서 에이전트 팀 참여 (Headless Mode)

> 개발자로서, Electron 앱 없이 각각의 터미널 창에서 Claude Code를 실행하되, 동일한 팀 메시지 채널에 연결하여 에이전트 팀의 일원으로 동작하게 하고 싶다.

**인수 조건:**
- `claude --channels server:claudeteam-agent -- --team shop --name 백엔드` 형태로 독립 터미널에서 팀에 합류 가능
- 팀 설정(team config)은 공유 파일(`.claudeteam.json`)로 관리되며, 여러 터미널이 동일 설정을 참조
- Message Router는 별도 데몬 프로세스로 실행되어 Electron 앱 없이도 동작 가능
- Electron 앱과 Headless 모드를 혼용할 수 있다 (일부는 앱, 일부는 독립 터미널)

### US-08: 크로스 레포 파일시스템 읽기

> 에이전트로서, 다른 에이전트의 레포지토리에 있는 파일을 직접 읽어서 분석하고 싶다. 메시지 인라인 삽입 대신, MCP 도구를 통해 필요한 파일을 직접 조회할 수 있어야 한다.

**인수 조건:**
- `team_read_file` MCP 도구로 허용된 경로의 파일을 직접 읽을 수 있다
- `team_list_files` MCP 도구로 다른 에이전트의 레포 디렉토리 구조를 탐색 가능
- `team_search_files` MCP 도구로 다른 레포에서 패턴 기반 파일 검색 가능
- 파일 접근은 팀 설정의 `allowedReadPaths` 범위 내에서만 허용된다

## 4. 비기능 요구사항

### 4.1 성능
- 에이전트 3~5개 동시 실행 시 앱 메모리 사용량 500MB 이하
- 메시지 전달 지연 시간 < 2초 (로컬 웹훅 기준)
- xterm.js 렌더링 60fps 유지

### 4.2 플랫폼
- macOS 12+ (1차 지원)
- Windows 11, Ubuntu 22.04+ (2차 지원)
- Claude Code v2.1.80+ 필수

### 4.3 보안
- 외부 네트워크 미사용 (모든 통신은 localhost)
- 파일 접근은 사용자가 지정한 디렉토리 범위 내에서만 허용
- 에이전트 간 통신 로그 로컬 저장 및 열람 가능

---

## 5. 제외 범위 (Out of Scope)

- 클라우드 기반 원격 에이전트 실행 (로컬 전용)
- Telegram/Discord 등 외부 메신저 연동 (자체 내장 채널 사용)
- 에이전트 간 자율 대화 (반드시 사용자 또는 규칙 기반 트리거)
- Git 자동 커밋/푸시 (에이전트가 제안, 사용자가 승인)
